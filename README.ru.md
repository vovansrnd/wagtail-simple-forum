# wagtail-simple-forum

**Добавляет встроенный в Wagtail форум: категории, разделы, темы, сообщения, модерацию, личные сообщения, уведомления, поиск и инструменты переноса данных из старого приложения форума.**

## Основные возможности

- Иерархия «категория → раздел → тема → сообщение» и счётчики активности.
- Личные сообщения с папками входящих и цепочками бесед.
- Антиспам для гостей, модерация, поиск и ограничение частоты запросов.
- Импорт старого форума и переадресации; перед переключением трафика проверьте dry-run.

## Требования и совместимость

- Заявленные зависимости: `Wagtail >= 6.0; django-prose-editor >= 0.26; nh3 >= 0.2.14`.
- Совместимость Python, Django и Wagtail нужно проверять совместно. Нижняя граница зависимости пакета не является подтверждением поддержки каждой версии.

В метаданных пакета заявлен Wagtail >= 6.0, однако нижняя граница зависимости не доказывает совместимость со всеми версиями. В архиве нет полной автоматизированной матрицы Django/Wagtail. Перед обновлением production проверьте точные версии, базу данных, файловое хранилище и настройки развёртывания на тестовом стенде.

## Установка

Установите пакет в то же виртуальное окружение, где работает ваш проект Wagtail:

```bash
pip install wagtail-simple-forum
```

Добавьте приложения в указанном порядке, сохранив остальные приложения и зависимости проекта:

```python
INSTALLED_APPS = [
    # Сохраните и остальные зависимости Django/Wagtail, требуемые проекту.
    "django_prose_editor",
    "wagtail_simple_forum",
]
```

Подключайте URL форума **до универсального маршрута Wagtail**. Если включены legacy-переадресации, они тоже должны находиться до catch-all.

```python
from django.urls import include, path
from wagtail_simple_forum.legacy_urls import urlpatterns as legacy_forum_urls
urlpatterns = [
    path("forum/", include("wagtail_simple_forum.urls")),
    *legacy_forum_urls,
    # Маршрут legacy должен идти до catch-all Wagtail.
]
```

Выполните `python manage.py migrate wagtail_simple_forum`.


## Первоначальная настройка

Минимальный пример для начала работы. Замените имена моделей, поля API и URL на соответствующие вашей конфигурации.

```python
from django.urls import include, path
from wagtail_simple_forum.legacy_urls import urlpatterns as legacy_forum_urls

urlpatterns = [
    path("forum/", include("wagtail_simple_forum.urls")),
    *legacy_forum_urls,  # Маршрут legacy должен идти до catch-all Wagtail.
]
```

Выполните `python manage.py migrate wagtail_simple_forum`. Для старого приложения `forum` сначала запустите `python manage.py forum_import_from_app --source forum --dry-run`.

Перед импортом старого форума сделайте резервную копию базы и выполните `--dry-run`. Не отключайте старое приложение, пока импорт и проверки не завершены.

### Важные замечания

URL форума и legacy-переадресации должны стоять до catch-all маршрута Wagtail. При переносе старого форума сначала сделайте резервную копию и запустите импорт с `--dry-run`.

## Безопасность и эксплуатация

- Поддерживайте зависимости в актуальном состоянии. Для пользовательского HTML используйте предусмотренную очистку и вывод; не применяйте безусловный `|safe` к сохранённым комментариям или сообщениям форума.
- Проверьте миграции и разрешения под обычной учётной записью, пользователем с ограниченными правами, модератором и администратором.
- В многосайтовой конфигурации проверьте каждый настроенный домен и неизвестный домен. Если Site не найден, запрос не должен расширяться до записей всех сайтов.
- Считайте API-токены, SMTP-пароли и приватные URL секретами. Не коммитьте их в Git и не вставляйте в публичные отчёты об ошибках.
- Сделайте резервные копии базы и медиа перед миграциями, массовым перемещением файлов, импортом или первой массовой публикацией. Сначала выполните операции на тестовом стенде.

## Рекомендуемые сочетания

- `wagtail-mptt-comments` дополняет форум комментариями под статьями; `wagtail-prose-editor-images` нужен только для собственных Prose-полей.
- Каталоги изображений независимы от данных форума.
